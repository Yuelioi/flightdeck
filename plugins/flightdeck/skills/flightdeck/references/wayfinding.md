# Wayfinding

Use Wayfinding only when the Work Goal is clear but the delivery route is not. It is an optional
Plan phase, not a separate Map, tracker, lifecycle, or skill state system.

1. Record stable scope and out-of-scope boundaries in Work context.
2. Add only the route-shaping questions that can already be stated precisely as linked Decision
   Slice items under a `Wayfinding` Plan heading.
3. Keep unresolved in-scope uncertainty that cannot yet be formulated under an optional
   `Not yet specified` heading without checkboxes. Do not invent a complete plan through fog.
4. Select one Decision Slice and put it in the Work page's Next. Choose the method its uncertainty
   needs: Research for facts, Prototype for behavior, Grilling for a user decision, or an ordinary
   Task for a concrete blocker.
5. When the decision is verified, record stable meaning in context when appropriate, complete its
   Plan item, promote newly precise questions from `Not yet specified`, and choose the next Slice.
6. Create separate Delivery Slice items for implementation. A completed decision never means its
   decided implementation has been delivered.

Plan links use readable outcome names. Do not add types, labels, claims, dependency graphs, Map
files, automatic branches, commits, or tracker operations. One top-level session may coordinate
child-agent research, but it alone updates the authoritative Work state.
