# Upgrade a workspace

Treat older or divergent Flightdeck documents as evidence, not as input to a versioned migration
protocol. There is no format detector, compatibility matrix, schema, or automatic migration script.

1. Inspect the actual deck, Work pages, context, plans, Slice-like documents, references, Knowledge,
   repository instructions, and live Git state.
2. Identify the current Goal, lifecycle truth, Current, executable Next, stable context, ordered
   completion, durable local detail, useful supporting material, and reusable guidance by meaning
   rather than filenames or legacy fields.
3. Preserve ambiguous material at its current path and surface the uncertainty. Ask before an
   irreversible choice instead of guessing from a claimed version.
4. Reshape active recovery into the current Deck, Work, Context, optional Plan, linked Slice, and
   References model. Remove duplicated authorities only after their current value is represented.
5. Keep terminal Work stable when already in the current model. Retire obsolete internal machinery
   according to user authorization and ordinary Git history; do not create a compatibility layer.
6. Prove that a fresh session can recover the selected Work progressively and that links and live
   repository state agree.

Upgrade edits visible Markdown and related repository instructions only as authorized. It does not
stage, commit, push, tag, publish, or rewrite history automatically.
