# Split skills by invocation and disclose detail by branch

A separate skill is justified when users need to invoke that capability independently. Do not split
every phase or paragraph into a competing public skill, and do not copy the same conditional rules
across several entry points.

Keep the main skill as a concise router for closely related intents. Put branch-specific procedure
in nearby references and load only the branch that matches the request. Create another public skill
when it owns a genuinely independent method, output, or trigger.

This keeps discovery precise, resident context small, and each rule authoritative in one place.
