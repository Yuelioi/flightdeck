# Knowledge playbook implementation context

## What matters

The implementation must make Work use Knowledge as a demand-grown advisory playbook without
restoring the retired routing runtime. The source skill, installed copy, English and Chinese public
documentation, format guide, and repository vocabulary must describe the same behavior.

## Decisions

- Knowledge stays lazy and is selected only for a current project-specific practice question:
  existing Work links first, then a bounded subject, filename, and heading search.
- Guidance advises judgment and does not prove compliance; enforceable rules belong in tests,
  validators, or repository instructions.
- Persist a Knowledge link only for recovery value: immediate need in Next, continuing support in
  References, ordinary consultation unrecorded.
- Promote only verified, plausibly reusable, self-contained project-specific positive guidance.
- Rewrite or remove disproven guidance; unresolved replacement research stays in Work without
  Knowledge status metadata.
- Keep one independently applicable practice per organic subject path and add topics only from
  qualifying real Work conclusions.

## Boundaries

- Do not modify any file under `flightdeck/knowledge/` for this implementation.
- Do not add a Knowledge index, registry, taxonomy, routing field, activation rule, revision,
  history, stale flag, recheck ledger, or consultation receipt.
- Preserve unrelated uncommitted release-completion and research documents.
