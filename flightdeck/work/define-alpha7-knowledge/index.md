# Define alpha.7 Knowledge usage

## Goal

Decide what belongs in alpha.7 `flightdeck/knowledge/` and how a Work discovers, applies, links,
and contributes reusable guidance without recreating the retired routing runtime.

## Status

Finished

## Current

The accepted eight-part model defines Knowledge as a demand-grown project operating playbook and
defines how Work discovers, applies, links, promotes, and maintains it without runtime metadata.
Root vocabulary and ADR-0026 record the boundary. The audit keeps all eight current files, finds no
evidence-backed coverage gap, and no Knowledge content changed during this Work.

## Next

None.

## Progress

- Inspected the published Knowledge contract, root glossary, all eight existing Knowledge files,
  recovery behavior, and output-routing boundaries.
- Confirmed the Finished alpha.7 implementation and release Works remain terminal.
- Defined Knowledge's primary role and exclusions and recorded the canonical term in root context.
- Defined need-triggered, link-first, subject-bounded Knowledge discovery without eager loading.
- Defined Knowledge as advisory input, with enforceable rules owned by executable authorities.
- Limited durable Work links to immediate or continuing recovery value without consultation logs.
- Required verified, plausibly reusable, self-contained guidance for promotion without a repetition
  counter.
- Assigned stale-guidance containment to the detecting Work without status metadata.
- Chose independently applicable topic files and organically growing subject folders without an
  index or registry.
- Made Knowledge demand-grown from verified Work conclusions rather than pre-seeded coverage.
- Received explicit shared-understanding confirmation for the complete eight-part model.
- Recorded the architecture in ADR-0026 and audited all eight current Knowledge documents.
- Passed whitespace, 100-file Markdown link, vocabulary/ADR alignment, and unchanged-Knowledge-tree
  verification.
